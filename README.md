# rosiwit_ws — 室内移动机器人（SLAM / 导航 / 感知 / 仿真）

本仓库是室内移动机器人的整机软件工作区，包含 ROS1（生产）与 ROS2（迁移中）两套栈。

## 当前状态

| 能力 | 现状 |
|---|---|
| 定位 | FAST-LIO2 前端 + GICP 局部匹配 + 9 状态 ESKF；10 Hz 输出；静态抖动 5–6 mm（eskf），单帧最大 21 mm |
| LIVO（激光+惯性+相机） | FAST-LIVO2 已移植进核心（零 ROS），标准节点 `config:=fast_livo2_ntu.yaml` 直接跑；NTU eee_03 整段 **ATE 0.234 m**（离线回放 0.237 / 独立包 0.257）；单目相机也能上色（灰度） |
| 建图 | 关键帧子图 + PCD 地图 + 2D 栅格 + 叠加层（半静态变化沉淀，不重写底图）；LIVO 额外输出彩色地图 `map_rgb.pcd` |
| 回环 / 重定位 | Scan Context 回环；全局重定位改为 **ScanContext 候选级联**：252k 点地图/20 个合成场景 **p95 3.3 s、召回 100%、误锁 0%**（原 FPFH 整图 RANSAC 22–45 s，现仅作无 `.scdb` 兜底） |
| 导航 | Hybrid A* + MPPI + footprint-aware 控制、窄道检测、速度限制、未知区代价 |
| 感知 | ROS2：AVM、地面纹理、QR、相机低矮障碍检测；ROS1：无 3D 语义/跟踪 |
| 仿真 | ROS1 Gazebo classic；ROS2 有 world/models/urdf |
| 平台 | 生产 ROS1 Melodic（2023 EOL）；ROS2 工作区已成型（自研 nav/perception/exploration/coverage/app） |
| 算力 | 8 核 ARM，无 GPU；SLAM 节点 RSS ≈ 1.0–1.2 GB；LIVO 长序列处理约 7.5 帧/s（未实时） |

## 1. 3DGS 地图（P2，4–6 周）

**目标**：把站点扫成可浏览、可量测的高保真 3DGS 模型，用于运维、验收、数字孪生和地图质量检查。**不进入实时定位/控制环。**

**为什么**：现有 PCD + 2D 栅格只能看几何，现场验收/远程排障缺少“像照片一样”的证据；3DGS 还能暴露建图漂移、遮挡和变化区域。

**工作包**
1. 采集管线：图像 + 激光 + SLAM 位姿同步；曝光/白平衡锁定；输出 MCAP/rosbag + 位姿 + 内参。
2. 位姿初始化：优先用 SLAM 位姿，COLMAP 只做精化；失败帧剔除策略。
3. 训练：gsplat/nerfstudio，站点分块训练；SH 阶数/量化/剪枝压缩。
4. 服务与查看：导出点云/网格给 RViz/Foxglove；Web 查看器；与 PCD 地图同版本号。
5. 质量指标：PSNR/SSIM、几何误差（对 PCD）、覆盖空洞、漂浮物比例；自动报告。
6. 与地图版本绑定：`<site>/<map_version>/gsplat/` + metadata；回滚不依赖 3DGS。

**里程碑**
- M1：单站点 1000 m² 重建跑通，几何误差 < 3 cm。
- M2：压缩后 < 500 MB，工作站加载 < 3 s。
- M3：验收报告模板 + 与地图版本联动。

**验收**：一个真实站点的 3DGS 可在 Web 打开；与 PCD 同坐标系对齐；几何误差 p95 < 3 cm；不影响现有定位链路。

**风险**：光照变化、动态物体、存储；相机标定误差会直接进模型。

**不做**：不用 3DGS 做实时定位（至少本期不做）；不替代 PCD/栅格。

## 2. 重定位提速（P0，3–4 周）

**目标**：冷启动/被搬动/切图后的全局重定位从 22–45 s 降到 **p95 < 5 s**，召回 > 95%，误锁 < 1%。

**为什么**：这是当前最直接的用户体验差距；FPFH 在 110 万点全图上做 RANSAC，代价随地图线性增长。

**工作包**
1. 基线与数据集：收集 ≥ 20 个重定位场景（冷启动、被搬动 1–5 m、光照/堆货变化），统一回放与计时脚本。
2. 粗检索：Scan Context++ / STD 描述子，按关键帧建库；top-k（10–20）候选。
3. 几何验证：候选位姿 → GICP/NDT 精配准 → 多假设打分；保留现有 χ²/健康门控。
4. 时序确认：连续 2–3 帧一致才接受，抑制单帧误锁。
5. 备选：2D 栅格相关（平面站点）+ 3D 精化；学习描述子（AnyLoc/MixVPR）作为 P2 备选。
6. 工程化：描述子预计算与增量更新（叠加层变化后重建）；内存/CPU 预算。

**验收**：20 场景回放，p95 < 5 s、召回 > 95%、误锁 < 1%；单次检索 CPU < 200 ms；失败有明确原因码。

**进展（2026-11，详见 [docs/dev/relocalization-speedup.md](docs/dev/relocalization-speedup.md)）**

- 新增 core 基准工具 `tools/reloc_bench`：地图 + 轨迹 → N 个"冷启动"场景（地图内合成扫描 + 噪声/丢点），
  输出 p50/p95/max、召回、误锁，可复现、无 ROS 依赖。
- 瓶颈定位：`localizeTopK` 给 `3*top_k` 个候选每个都在**整图**上跑 GICP（251k 点地图单次 ~0.7 s）；
  `fpfh_ransac` 还在整图上做 3D 特征 + RANSAC。
- 改动：① 候选处裁局部子图（`reloc_submap_radius`，默认 30 m）；② ScanContext **候选级联**
  （候选位姿先打覆盖分淘汰，只精配前 3 个 + 高置信提前结束）；③ KD-tree 只建一次；
  ④ 管线二级精配同步裁子图；⑤ `fpfh_ransac` 默认迭代/轮数收紧并加 5 s 预算。
- 实测（NTU eee_03 地图 251,878 点 / 20 场景）：

  | localizer | 召回 | 误锁 | p50 | p95 |
  |---|---|---|---|---|
  | `bbs` 整图（基线） | 95% | 0% | 38.2 s | 42.7 s |
  | `scan_context` 整图（基线） | 100% | 0% | 19.6 s | 55.1 s |
  | **`scan_context` 两级/预算版（现状）** | **100%** | **0%** | **0.95 s** | **3.38 s** |

  → 已达到"p95 < 5 s、召回 > 95%、误锁 < 1%"，但场景是"地图内合成扫描"，
  还需现场 20 个真实场景（冷启动/被搬动/堆货变化）复验。

- 未完成：时序确认（连续 2–3 帧一致才接受）、叠加层变化后的 `.scdb` 增量更新（→ #10）、
  结构化失败原因码、110 万点生产地图 / 现场 20 场景复验（→ #8 的回归链路）。

**风险**：地图变化导致描述子失效；需要与叠加层刷新联动。

## 3. 3D 语义 / 动态目标（P1，8–12 周）

> 详细实施方案（前置深度相机、人员位置+速度）：[docs/superpowers/plans/2026-11-01-person-3d-semantics.md](docs/superpowers/plans/2026-11-01-person-3d-semantics.md)

**目标**：识别并跟踪人、叉车、托盘、推车等动态目标，给出 1–2 s 预测，接入局部规划与安全层。

**为什么**：现在只有点级动态过滤和相机低矮障碍，无法预测让行；人机混场是下一步产品化的核心场景。

**工作包**
1. 数据：采集人/叉车/托盘混场片段；标注 2D 框 + 3D 框/轨迹；建立类别与距离分层指标。
2. 检测：相机 2D 检测（YOLO 系）+ 点云抬升；或激光 3D 检测（PointPillars/CenterPoint）；CPU 侧保留现有低矮障碍兜底。
3. 跟踪与预测：ByteTrack/OC-SORT + 匀速/CTRV 预测，输出带不确定性的短时轨迹。
4. 语义层：实例表（类别/速度/置信度/最后观测），短时记忆；不写进静态地图。
5. 规划接入：动态障碍层（预测 footprint）、让行/绕行代价、社会距离；安全层保持独立硬约束。
6. 评测：MOTA/IDF1、分类召回、预测 ADE/FDE、混场导航成功率、误停率。

**验收**：三类目标在 0.5–8 m 的召回 > 90%；预测 1 s ADE < 0.3 m；混场场景成功率 +20%，误停不增加；端到端延迟 < 100 ms。

**风险**：标注成本、遮挡、GPU 预算；ROS1/ROS2 双栈接入顺序（建议 ROS2 先行）。

## 4. 电梯 / 门禁（P1，8–12 周 + 现场）

**目标**：多楼层自主运输：呼梯 → 进梯 → 选层 → 出梯；门禁/闸机通行。

**工作包**
1. 接口层：电梯（Modbus/CAN/HTTP/厂商 SDK）、门禁（Wiegand/OSDP/HTTP）抽象；超时/重试/降级。
2. 状态机：呼梯、等门、进梯（位姿对齐）、选层、出梯、异常退出；每步超时与安全回退。
3. 多楼层地图：楼层 ID + 地图分区/切换；楼层来源（电梯状态/气压/二维码）冗余。
4. 乘客检测：进梯前相机/激光判断是否超载/有人；门遮挡检测。
5. 安全：急停、门夹、超时困人处理、人工接管；与整机安全链路一致。
6. 仿真/HIL：电梯门/轿厢模型 + 接口 mock；现场联调 checklist。

**验收**：连续 100 次乘梯成功率 > 99%；无困人/夹人事件；单次乘梯额外耗时 < 30 s；异常全部可恢复或安全停机。

**风险**：电梯厂商配合、现场许可、消防/法规限制；这是集成项目，不是纯软件。

## 5. Isaac 仿真（P2，6–8 周）

**目标**：GPU 写实仿真 + 场景化自动回归 + sim2real 校准，支撑感知/规划/学习策略。

**工作包**
1. 选型与接入：Isaac Sim / Isaac Lab 版本锁定；ROS2 bridge；URDF → USD；传感器模型（激光、RGB-D、IMU 噪声）。
2. 场景：站点 CAD/点云导入 → 碰撞+视觉；程序化堆货；动态角色（人/叉车）。
3. 场景库：对接、窄道、人横穿、电梯、堆货变化；每个场景有成功判据。
4. 回归：夜间自动跑批，输出成功率/碰撞/耗时；与实车日志对比。
5. sim2real：噪声/延迟/打滑标定；域随机化；关键指标差距 < 10%。
6. 数据：可选合成数据用于感知预训练。

**验收**：10 个场景自动回归；确定性回放；关键指标 sim2real 差距 < 10%；CI 可在 GPU runner 上跑。

**风险**：GPU 成本、资产制作工作量大；不要试图 1:1 复刻现场。

## 6. 学习型局部策略（P2，12–16 周）

**目标**：在人机混场/窄道博弈中超过 MPPI，同时**不降低安全指标**。

**工作包**
1. 数据：记录 MPPI/人工遥操作轨迹 + 局部代价图 + 感知目标；50–100 h；失败案例重采样。
2. 路线 A（优先）：学习型 critic/残差给 MPPI 加权——保留几何可行性与硬约束，风险最低。
3. 路线 B：Diffusion/Flow 策略输出局部轨迹，外套 MPPI/急停安全盾（policy 提议、shield 否决）。
4. 路线 C（探索）：ViNT/NoMaD 类图像目标导航，用于探索而非精确对接。
5. 训练/评测：离线模仿 + 仿真 RL 微调；Isaac 批量评测；实车 A/B。
6. 安全：footprint、速度、E-stop 永远由经典层兜底；策略输出必须可解释/可回放。

**验收**：混场/窄道成功率 +20%；碰撞/急停不增加；Orin 上推理 < 20 ms；关闭策略可一键回退 MPPI。

**风险**：数据与训练成本高；安全责任需要可解释的 shield；不建议直接端到端控车。

## 7. LIVO 实时化与长序列稳定（P1，4–6 周）

**目标**：LiDAR+IMU+相机（FAST-LIVO2）在长序列上保持 **10 Hz 不掉帧**，精度相对离线回放不退化 > 10%。

**为什么**：LIVO 已经移植进核心并在 NTU eee_03 上跑出 ATE 0.234 m，但整段 1814 帧要 ~240 s（**7.5 帧/s**）——
体素地图与视觉稀疏地图随帧数增长，单帧耗时从 10 ms 涨到 130 ms。现场相机标定/曝光不锁定时掉落更多。

**工作包**
1. 地图裁剪：开 `map_sliding`（半图尺寸/滑窗阈值），观察 ATE 与内存（当前 RSS 随序列线性涨）。
2. 视觉侧限流：sparse map 上限、patch 数量上限、按跟踪质量降频 VIO。
3. 线程/内存：IMU/LiDAR/图像三队列的背压策略（现在落后时会合并位姿，`/lio_odom` 只剩 ~3 Hz）。
4. 相机侧工程：曝光锁定、内参/畸变在线校验（单目时给出"仅灰度上色"的明确提示）。
5. 基准：用 `livo_replay` + 至少 3 段现场包（含长走廊/上下坡）建回归基线。

**验收**：3 段 ≥ 3 min 的包，处理速率 ≥ 10 帧/s；ATE 相对离线回放退化 < 10%；RSS < 1.5 GB 且不随序列线性增长；`/lio_odom` 保持 ≥ 9 Hz。

**风险**：裁剪会改变地图边界行为（回环/重定位依赖地图完整性），需要与 #10 地图版本联动。

## 8. 回归与场景化 CI（P1，3–4 周）

**目标**：SLAM（LIO/LIVO）、重定位、导航三条链路每次改动自动回归，**指标退化 > 5% 就报警**。

**为什么**：这一轮里"看起来像算法坏了"的问题至少有 4 个其实是工程缺陷（单目上色越界、`best_effort` 丢 35% 点云、
`pcl::VoxelGrid` int32 溢出、点云宽高为 0 触发 SIGFPE）。这些只要有一条 nightly 回放就能立刻定位。

**工作包**
1. 工具固化：`livo_replay`（ATE）、`tools/reloc_bench`（p95/召回/误锁）、`localization_eval`、仿真 nav runner。
2. 指标基线：每条链路一份 JSON 基线（ATE、p95、成功率、碰撞数），提交到 `docs/artifacts/`。
3. CI：夜间跑（本机 x86 + ARM runner），失败输出对比报告；PR 只跑 1 分钟子集。
4. 数据管理：包/地图用哈希命名，缺失时跳过并显式标记"未覆盖"。

**验收**：三条链路每夜自动跑；人为注入一次精度退化（如关掉 IMU 插值）能在 1 天内被报警；报告 1 页可读。

## 9. 视觉重定位与视觉回环（P1，6–8 周）

**目标**：在光照/堆货变化、激光重复结构（长走廊、货架）下也能重定位，减少纯激光的歧义误锁。

**为什么**：现在重定位只靠 ScanContext + 几何精配，重复结构里靠"best - second"门控；LIVO 已经能给出带视觉约束的位姿，
但视觉信息还没有进入重定位/回环。

**工作包**
1. 视觉描述子库：沿关键帧存图像描述子（NetVLAD/AnyLoc 或轻量 DBoW），与 `.scdb` 同版本。
2. 融合检索：激光 + 视觉候选求交/加权，几何精配后仍走 χ²/健康门控。
3. 视觉回环：LIVO 的 VIO 约束接入现有 pose graph（`visual_constraint_source` 已有骨架）。
4. 光照鲁棒：直方图均衡/曝光归一；夜间/逆光场景降级为纯激光并记录原因码。

**验收**：重复结构场景误锁 < 1%（相对纯激光降低一半）；光照变化场景召回 > 90%；单次检索 CPU < 300 ms。

## 10. 地图版本与生命周期（P1，3–4 周）

**目标**：`map.pcd` / 栅格 / 彩色地图 / `.scdb` / 叠加层同版本原子更新，重定位与定位不会读到半成品。

**为什么**：重定位提速后，`.scdb` 成为热路径依赖；但叠加层变化（堆货/改布局）后描述子库不会重建，
`updateEnvironment()` 也还没接 ScanContext 库 —— 现场表现就是"地图变了，重定位开始变慢/失效"。

**工作包**
1. 清单文件：`<map>/manifest.json`（版本号 + 各文件哈希 + 生成参数），所有产物同一事务写。
2. 增量重建：叠加层变化后只重建受影响区域的描述子/子图，后台线程完成再切换。
3. 回滚：保留上一版本 N 份，读失败自动回退；`SaveMap` 返回版本号。
4. 与 #2 联动：`.scdb` 缺失/版本不匹配时明确降级到 `fpfh_ransac`（当前是静默返回 0）。

**验收**：叠加层更新后重建 < 30 s（1000 m² 站点）；版本不匹配时重定位给出明确原因码而不是超时；回滚演练通过。

## 11. 在线时间/外参标定落地（P2，2–3 周）

**目标**：时间偏移自动收敛到 < 5 ms、安装 yaw < 0.5°，并能在标定不稳定时安全回退。

**为什么**：核心已有 `OnlineTimeCalibrator` / `YawExtrinsicCalibrator`（只估计、不偷改状态），但没接实车；
这一轮在数据集上就踩到"TF 缺失/仿真时钟不前进导致初始化卡死"这类时间相关坑。

**工作包**
1. 接实车：IMU 角速度 vs LIO 角速度互相关窗口调参；只在静止/匀速段生效。
2. 写回策略：置信度门控 + 变化率限制 + 一键回滚（`calibration.apply` 已存在）。
3. 与 TF 的关系：有 TF 用 TF，无 TF 用配置外参并 WARN（现在已是这个行为），标定结果只作为附加修正。
4. 评测：录制 20 段不同温度/负载的数据，标定前后 ATE/残差对比。

**验收**：时间偏移估计误差 < 5 ms、yaw < 0.5°；误标定（把好参数改坏）0 次；关闭标定可一键回退。

## 暂不追的方向

- **端到端 VLA / 基础模型控车**：工业场景的可解释性与安全责任不清晰，短期不进控制环。
- **NeRF/3DGS 用于实时定位**：收益/成本比低，先做地图 QA 与孪生。
- **多机调度/VDA 5050**：若产品定位是单机，这一层不建；要建就按标准设计，不自造协议。
- **人形/足式**：与本产品形态无关。
- **自研激光雷达驱动/点云容器格式**：成熟驱动 + 通用 PointCloud2 够用，收益低于维护成本（LIVO 的 `t` 字段解析已经踩过一次坑，但那是解析 bug，不是格式问题）。
