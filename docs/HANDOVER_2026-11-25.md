
### 1.4 子图桥接模式（overlay 顶不住时的维持手段）

```
fitness_overlay < credible 连续 anchor_patience(5) 帧
  → [anchor] switch to submap (bridging)     ← 只切目标到子图, 不重建!
  目标 = 子图 pointsWorld(), 边建图边定位, 子图自更新(accepted 帧持续写入)
每 probe_period(50 帧≈5s):
  对 overlay(底图+w) 做一次探测匹配
  fitness ≥ reloc_accept_score(0.85) → 重锚成功:
      zip-up: C = T_重锚位姿 ∘ T_切换时位姿⁻¹, 作用于子图全部内容+锚
      切回 overlay 锚定, 日志含 drift=M
```

- **子图从定位成功起就一直在建**（building ahead），切换时**不 reset**——
  此刻重建必然是薄图出错（用户明确要求）。
- 提交：`9ed6907`（桥接模式 + zip-up）。

### 1.5 33° 之谜的定位（`[pose_cmp]`）

`[pose_cmp]` 证明：**匹配器自己输出 roll≈33°**（guess/先验同值），中间无变换加入。
33° ≈ URDF `base_link→lidar` 的 pitch 39.37°。结合 `up_z=1.000`（扫描系地面水平），
判定：**核心位姿帧含安装 pitch，而点云帧不含**（驱动已水平化输出，标签同名但轴不同）。
该结论支撑了 §1.3/§2 的所有换算。逐帧 z 约束（`[planar]`）在此帧系下仍会 `jump`，
见 §3 遗留 2。

## 3. 需要做的事（按优先级）

### P0 —— 0.2.18 装机验证（arm64 已构建，装上即可）

验证四步（日志都在）：

```
1. [slam_algo] init pose footprint->lidar: z 0→0.984   车底贴地
2. 正常运行: cov_base≥0.75 → 目标=overlay; [session_map] open (building ahead)
3. [anchor] switch to submap (弱锚 5 帧) → 目标=子图, 边建图边定位
4. 探测重锚: fitness≥0.85 → zip-up (日志 drift=..m) → 切回 overlay
```

### P1 —— overlay 计票的 `anchorOk` 口径（自引用残余风险）

`onLocalized` 的写图门控仍是 `allowMapInsert && anchorOk(res)`，而 `anchorOk` 是对
**当前目标**（桥接时含子图）算的 —— 自引用残余。改法：`anchorOk` 判据换成
`cov_base ≥ credible`（对底图的覆盖率），与锚定切换同源。

### P2 —— `[planar]` 逐帧 z 约束的系一致问题

核心位姿带安装 pitch（nm_z≈0.85），`scan_plane` 每帧 `jump`。
两个方向二选一：把约束换到与位姿一致的系；或桥接/探测重锚成功后由 overlay
承接逐帧维持。**在 P0/P1 验证前不动**。

### P3 —— 退化部分更新的平移泄漏（隐患）

`degeneracy_partial_update` 里 `e2.head<3>()` 直接当旋转轴角用，而特征基混合了
平移分量 —— 本次实机未触发（DegeneracyProbe=0），建议加旋转角上限（如 ≤5°）。

### P4 —— 反光板绝对约束（`onAbsolute` 入口已就绪）

`LocalizationPipeline::onAbsolute(pose, cov)` 已实现（门控互补融合），缺：
现场反光板 + 一个"从点云提反光板 → map 系位姿"的检测节点（强度阈值聚类即可）。
完全变化场景下的工业标准解。

### P5 —— 长走廊实测

走廊 = 沿向平移不可观测，`cov_base` 会虚高（墙照常配上）。需要实测：
`correction_m` / `[DegeneracyProbe]` / 切子图时机。现有对策：退化部分更新 +
edge feature + odom 打滑判据。**注意**：桥接在走廊里同样自引用，长走廊里
overlay/子图的权重配比可能要现场调。

### P6 —— ELite 改进清单（`docs/anchor_submap_design.md` §5）

P3 overlap 分支（墙挪 0.5 m 也能修）+ P2 目标度 γ（慢走的人不成簇）
→ `collectNovel` 一处 ~60 行；P1 距离加权贝叶斯 hit/miss（替换 w±8）随后。

## 4. 关键机制速查

### 4.1 三层地图

| 层 | 出生 | 死亡 | 备注 |
|---|---|---|---|
| 底图(`map.pcd`) | 建图产物 | 无 | **只读备份**，永不修改 |
| 工作图(`map.overlay.pcd`) | 首次从 map.pcd 生成 | 无 | **匹配目标的数据源**；每 1h 且有变化落盘 |
| overlay 体素(w) | `collectNovel` 三道门 | miss 软删/硬删 | 只影响目标组成；烘焙进工作图=沉淀为永久 |
| 子图(会话地图) | `LOCALIZED`+fitness 达标开建 | 重定位/切图 reset | 桥接目标；**只切不重建** |

### 4.2 一次匹配的目标选择

```
fitness_overlay(res, 对工作图) ≥ credible → 目标 = 工作图 crop (overlay 已在里面)
fitness_overlay < credible 连续 5 帧     → 目标 = 子图 pointsWorld() (桥接)
子图模式每 50 帧 → 探测匹配(对工作图) → 达 reloc_accept_score → zip-up 切回
```

### 4.3 帧系约定（容易踩的坑）

```
核心位姿 = T_world←lidar，lidar 帧带安装 pitch(39.37°) —— R22≈0.84 是正常的
发布位姿 = composeRightInv(p_core, T_fp←lidar) —— 车底水平系
点云(frame=vanjee_lidar) 已被驱动水平化 —— 与核心位姿同系
IMU(vanjee_lidar_imu_packets) 轴带 38.4° 偏置(实测) —— 未处理, 已知问题
```
