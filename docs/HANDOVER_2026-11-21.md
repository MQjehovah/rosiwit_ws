## 3. 下一步实现：A 阶段（只记录，不影响决策）

**目标**：给现有 overlay 的体素加一列 `w`，把"高可信几何占比"变成可观测的量。

### 3.1 要改的地方

| 文件 | 改动 |
|---|---|
| `src/algorithms/localization/maintainer/overlay_map_maintainer.{h,cpp}` | 体素结构加 `uint8_t w`；hit 时 `w=min(255,w+8)`；复用现有 `rayCarve()` 在 miss 时 `w=max(0,w-8)`；`w==0` 删除 |
| 同上 | 新增 `double staticSupport(pose) const`：当前局部匹配点中 `w ≥ w_anchor` 的占比（或按点权重统计） |
| `localization_pipeline.cpp` | 1 Hz 打 `[quality] static_support=… anchor_age=… submap_pts=… state=…` |
| `slam_core/localization_stage_types.h` | `MaintainerConfig` 加 `w_anchor`（默认 128）、`shadow`（默认 true） |
| 配置 `config/default.yaml` | `maintainer.w_anchor / shadow`；**`decay_frames` 保持 0** |

### 3.2 数据结构（最小版）

```c
struct Voxel {
    uint8_t  w;          // 可信度 0~255
    uint32_t last_seen;  // 仅诊断, 不参与决策
};
```

**不要**引入时间衰减、区域掩码、`session_id`（方案 v3 §10 已列明原因）。

### 3.3 硬约束

1. **只在匹配健康时写 `w`**；`LOST` 期间只读
2. **写入门控要加 `static_support`**，不能只看 `fitness`（现场 0.80~0.84 的假锁会通过 `pose_confident`）
3. 子图/锚定（B/C 阶段）未做之前，`shadow=true`：`w` **不参与**任何决策

### 3.4 验收（跑一周）

- 每天导出 `w ≥ 128` 的点云 → 是否只剩立柱/墙体（这就是"静态底图"）
- `static_support` 分布：正常段 / 假锁段 / 堆货区各是多少
- 体素总量与内存实测（0.15 m）

### 3.5 之后的阶段（见方案 v3 §7）

| 阶段 | 内容 | 唯一新增模块 |
|---|---|---|
| B | 跟踪目标切到**滚动子图**（odom 系，覆盖式） | 新增 `rolling_submap.{h,cpp}` |
| C | `map→odom` 门控/冻结 + `DEGRADED`（`location_status=1`） | 无（改 `sendTransform`/`broadcastMapOdom` + 状态机） |
| D（可选） | `flip` 字段、评分策略可插拔（影子对比） | — |

## 5. 已知坑（都踩过）

| 坑 | 表现 | 处置 |
|---|---|---|
| deb 漏 `package.xml` | `xzrobot_start.py` 崩：`ResourceNotFound: rosiwit_slam_ros1`，SLAM 起不来 | 打包必须带 `share/rosiwit_slam_ros1/package.xml` |
| `robot_monitor` | 高 CPU 时 `gdb -batch -p <pid> -ex bt` 冻结节点（表现为"卡死"） | 二进制改名 `.disabled`（可逆），见 runbook §3 |
| 阈值链 | `credible ≤ reloc_accept`，乱改会重演假锁 | 只抬 `reloc_accept`（0.85），`credible` 保持 0.80 |
| `runOnLaneWithDone` 的 DoneFn | `ok` 只表示"任务执行过"，不是业务成功 | 结果要在任务体里存 |
| 设备编译时间 | 全量 ~15 min（原生）/ ~32 min（服务器 qemu `-j8`） | 不要用 `catkin_make install` 出包 |
| 设备负载 | 重定位预算过高时节点 4 核 | `retry_interval` / `fpfh_max_iter` 已调低 |
