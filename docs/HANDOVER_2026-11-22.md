## 2. 今天解决的三件事

### 2.1 锚判据：绝对 500 在窄过道不可达

实车窄过道整帧 **25,937 点只覆盖 2.4 m × 4.5 m**，0.4 m 体素只有 **176 个**，inliers 最多 ~105。
`anchor_min_inliers=500` 数学上不可达 → overlay 永远不写，`session_map` 永远开着。

改为（`include/algorithms/localization/maintainer/insert_gate.h`）：

```
anchor_ok = converged && accepted
         && (有 Hessian 时) smallest_eig_ratio >= 1e-3
         && inliers >= 50                         # 绝对下限
         && inliers >= 0.5 × visible              # 匹配前可见点数(动态滤除之前)
```

设备 0.2.2 实测：`inl=170 vis=172` → `anchor=OK`；`session_map` 10 帧好锚后关闭；
`novel_commits` 2~5/s，**overlay 第一次在真机开始沉淀**。

图：`docs/artifacts/2026-11-22/device_scan_extent_2026-11-22.png`（窄视野）、
`device_anchor_after_2026-11-22.png`（改判据前后）。

### 2.2 fitness 会被 `dynamic_filter` 抬高（诊断结论，未改）

实测地平面法向 `(-0.004, 0.143, 0.990)`，残差 **8.23°**（39° 安装角已由驱动补偿，`identity` 是对的，
**不要**按 URDF 再加 `imu_link`）。

- `dynamic_filter: true`（`dynamic_dist=0.4`）时：`source=123`，`fitness=0.86`；
- 关掉后：`source=160`，`fitness=0.72` → `LOST`。

也就是说 0.86 是在"筛掉 28% 不匹配点"之后算的，**选择偏差**。筛选本身让 ICP 拿不到远处点，
8° 残差在 2.8 m 外就超过 0.4 m 门槛。是否修（放宽 `dynamic_dist` / 标定 8° / 改用滤除前的覆盖率）
**留给下一步决定**，今天没动。

图：`docs/artifacts/2026-11-22/device_matcher_funnel_2026-11-21.png`、
`device_tilt_filter_2026-11-22.png`。

### 2.3 最小簇 bug（真 bug，已修）

原实现只看**本帧新体素**里有没有邻居；已经沉淀/被底图覆盖的邻居不算 →
贴着已有结构长出来的新几何被误判成孤立噪点，永远进不了 overlay。
改成按**整帧扫描的体素集合**计数（孤立点仍然被拒），单测 `ClusterCountsWholeScanNotOnlyNovel`
先红后绿。

### 3.1 仿真放箱子的坑（重要）

**地图系相对 Gazebo 世界系旋转了 ~166°**（机器人地图位姿 `(-1.1,0.1,-166°)`）。
按世界坐标放箱子会落到地图系里已被覆盖的位置 → `novel=0`。
正确做法：`world = R(-yaw_map) * map_delta`，例如"地图系正前方 2 m" → 世界 `(-1.94, 0.48)`。

### 3.2 仿真地图本身的已知问题

`loop_closure: scan_context` 存出来的 xzmap 关键帧点云 **每帧 z +1.4 m**（z 到 59 m）、
`/global_map` 飘到 `(-121,-623,190)`。仿真测试用"只保留第一个关键帧"的干净单帧地图：
`/tmp/kfclean.py`（保留 z 中位数与 kf1 一致的帧，写 `maps/clean/`）。

## 5. 日志字段速查

`[quality]`（1 Hz）：

```
persistency_cov / anchor_age / persistency_pts / novel_votes / novel_commits
state / shadow / persistency_anchor / fitness / anchor=OK|WEAK / inl / vis / eig
session_map / session_map_size / session_map_age
```

`[maint]`（每 100 帧）：

```
scan= 本帧扫描点数
seen= 落在已沉淀体素的点数
base= 被底图同体素挡住的点数
kd=   离底图 < delta_min 的点数
cand= 候选体素数
cluster_rej= 被最小簇拒掉的候选数
votes= 本帧计票数  commits= 本帧写入体素数
```

`[MatchProbe]`：`scan_points / source_points(动态滤除后) / target_points`。

## 7. 未决 / 风险

1. **`dynamic_filter` 的选择偏差**（§2.2）：真机报的 fitness 0.86 实际是 0.72。
   影响健康线 0.80/丢失线 0.75 的判定，建议单独立项：放宽 `dynamic_dist` 或改为
   "滤除前覆盖率"作为健康判据（但会牵动阈值链）。
2. **`anchor_min_ratio=0.5` 的普适性**：窄过道 0.60 能过；开阔区正确匹配应 0.7~0.9。
   若某些区域长期 0.4~0.5，需要看是不是地图/外参问题，不要直接降比例。
3. **簇阈值 3 在稀疏雷达上偏严**（仿真 16 线在 3~4 m 处点数密度只有 ~1.6 点/0.27 m³）。
   设备万集 722 更密，先在设备上看 `[maint] cluster_rej`；若同样偏高，考虑改成
   "0.5 m 半径内点数 ≥ N" 的密度判据。
